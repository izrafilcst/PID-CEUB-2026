Qual simulador usar?

Dois caminhos viáveis — diferem principalmente em velocidade de treino vs. facilidade de setup.

A ★

PyBullet (Recomendado para treino)

Biblioteca Python pura, headless por padrão. O ecossistema Gymnasium/SB3 foi construído em torno dele. Física de contato e atrito diretamente configurável via URDF.


Stack
PyBullet (física headless)
└── Gymnasium Env (line_follower_env.py)
    └── Stable Baselines3 PPO
    └── TensorBoard (métricas)

EDF → applyExternalForce() no CoM
Slip → lateralFriction configurável por superfície

Prós

  • 10–30× mais rápido que Webots (headless)
  • PPO roda ~5k steps/s numa CPU comum
  • Sem GUI overhead durante treino
  • pip install pybullet — sem configuração pesada
  • URDF do robô é portável e versionável

Contras

  • Visualização é básica (mas existe)
  • Modelo do robô precisa de URDF manual
  • Sensor infravermelho precisa ser simulado via raycast
B

Webots

Simulador 3D completo com GUI, modelos de motores DC e sensores embutidos. Melhor para visualização e debug, mas mais pesado para treino.


Stack
Webots (C++ ou Python controller)
└── Gymnasium wrapper via extern controller
    └── Stable Baselines3 PPO

EDF → Physics Node (força no CoM)
Sensores IR → DistanceSensor embutido

Prós

  • Sensores IR, encoders e motores DC embutidos
  • Visual excelente para debug
  • Não precisa simular raycast manualmente

Contras

  • Treino ~5–10× mais lento (GUI + overhead)
  • Gymnasium wrapper é mais complexo (extern controller)
  • Instalação pesada (~1GB)
  • Não roda fácil em servidor/CI headless
C

Híbrido: PyBullet treino + Webots validação

Treina no PyBullet (rápido, headless). Valida a política final no Webots (visual rico, sensores realistas). Mesmo env Gymnasium, dois backends.


Prós

  • Melhor dos dois mundos
  • Detecta overfitting ao simulator (sim gap)

Contras

  • Manter dois backends é trabalho extra
  • Faz sentido só se o projeto crescer além do MVP

Recomendação: A — PyBullet. Para RL você precisa de milhões de steps. PyBullet headless roda 10–30× mais rápido que Webots, e o Gymnasium/SB3 integra diretamente. O modelo do robô em URDF é simples para este tamanho de robô.
