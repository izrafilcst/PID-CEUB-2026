Três abordagens de arquitetura

Como estruturar o projeto simulator/ antes de escrever uma linha de código.

A ★

HAL-First (Recomendado)

Define as funções HAL como contrato Python abstrato primeiro. O Gymnasium env chama apenas a HAL. PyBullet é um dos backends. Quando portar pro ESP32-S3, só troca o backend.


Estrutura
simulator/
├── hal/
│   ├── base.py          # ABC: read_sensors, read_encoders…
│   └── pybullet_hal.py  # implementação PyBullet
├── envs/
│   ├── line_follower_env.py  # Gymnasium — usa só HAL
│   └── physics.py           # modelo EDF, slip, pista
├── models/
│   └── model_data.h         # TFLite C array
├── train.py
├── evaluate.py
└── export_tflite.py

Prós

  • Porta pro ESP32-S3 sem reescrever env
  • Testável: mock HAL para unit tests
  • Alinhado com o CLAUDE.md já escrito
  • Separação clara sim ↔ lógica de controle

Contras

  • ~1 dia a mais de setup inicial
B

Sim-First (acoplado)

Escreve o env diretamente acoplado ao PyBullet. Sem abstração HAL. Porta pro hardware depois, quando necessário.


Estrutura
simulator/
├── envs/
│   └── line_follower_env.py  # chama PyBullet direto
├── train.py
└── export_tflite.py

Prós

  • Mais rápido de prototipar
  • Menos arquivos inicialmente

Contras

  • Portabilidade exige refactor completo depois
  • Sem separação clara sim ↔ lógica
C

Dual-Backend (sim + serial real)

HAL tem dois backends completos: PyBullet (sim) e Serial/USB (hardware real via protocolo). Um flag --backend=sim|real troca na hora. O mesmo script de treino roda no hardware.


Prós

  • Treino em hardware real (sim-to-real gap zero)
  • Validação automática sim vs. real

Contras

  • 2× mais trabalho (HAL serial é complexo)
  • Treino no hardware é lento (1 env, sem paralelismo)
  • Faz sentido só depois de validar no sim

Recomendação: A — HAL-First. O contrato read_sensors / read_encoders / set_motors / set_edf já está no CLAUDE.md. Formalizar isso como ABC Python hoje custa 1 dia e elimina um refactor completo na hora de portar pro ESP32-S3. O Approach C (dual-backend) pode ser adicionado depois, se necessário.
