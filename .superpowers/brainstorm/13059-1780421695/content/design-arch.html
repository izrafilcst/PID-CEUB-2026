Design: Arquitetura Geral

Seção 1 de 4 — visão de cima. Confirme antes de avançar.

Camadas do sistema
── Treino (Python, offline) ─────────────────────────────────
 train.py
  └── SB3 PPO (SubprocVecEnv × 8)
     └── LineFollowerEnv (Gymnasium)
         └── HAL.PyBulletHAL
             └── PyBullet (física, pista, EDF, slip)

── Export (Python, uma vez) ─────────────────────────────────
 export_tflite.py
  └── SB3 policy → ONNX → TFLite FlatBuffer
     └── xxd -i model.tflite → models/model_data.h

── Deploy (C++, ESP32-S3) ───────────────────────────────────
 src/control/MLController.h/.cpp
  └── TFLite Micro (model_data.h)
     └── obs[14] → Δpwm_L, Δpwm_R, pwm_EDF
         → somado à saída do CascadeController existente

Fronteiras de responsabilidade

Módulo Responsabilidade Arquivo
hal/base.py ABC com 4 métodos — contrato sim→real Python
hal/pybullet_hal.py Implementa ABC via PyBullet + raycasts Python
envs/physics.py Modelo EDF, slip, geração de pista Python
envs/line_follower_env.py Gymnasium: obs, reward, step, reset Python
train.py SB3 PPO, hiperparâmetros, checkpoints Python
export_tflite.py SB3→ONNX→TFLite→C array Python
MLController.h/.cpp Inferência TFLite Micro no ESP32-S3 C++

A LineFollowerEnv nunca chama PyBullet diretamente — só chama hal.read_sensors(), hal.read_encoders(), etc. Isso garante que o env funciona idêntico com qualquer backend futuro (serial, mock de teste).
