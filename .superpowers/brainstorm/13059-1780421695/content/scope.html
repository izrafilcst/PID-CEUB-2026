O que entra no escopo do simulador?

O CLAUDE.md descreve dois modos bastante diferentes. Qual(is) você quer construir agora?

A

Modo Corsa apenas

Mapeamento de pista na 1ª volta via odometria (raios de curva + comprimento de retas), feedforward otimizado na 2ª volta. Sem ML. Mais rápido de implementar.


Prós

  • Física simples (encoder + PID)
  • Resultado direto em performance
  • 2–3 semanas

Contras

  • Não generaliza para pistas com sujeira
  • Não usa ML / EDF
B

Modo Offroad apenas

Rede neural (PPO/SAC via Stable Baselines3) para lidar com slip, sujeira, inércia. EDF simulado como força no CoM. Export: Keras → TFLite → C array para o ESP32-S3.


Prós

  • ML completo: treino → deploy real
  • Cobre cenários adversariais

Contras

  • 6–8 semanas mínimo
  • Física de slip exige calibração cuidadosa
  • TFLite Micro tem restrições no ESP32-S3
C

Ambos (sequencial)

Corsa primeiro (fundação do ambiente Gymnasium + física), Offroad depois (layer de ML por cima). Faz sentido técnico — o env de Corsa é reaproveitado.


Prós

  • Fundação robusta antes do ML
  • Cada fase entrega algo testável

Contras

  • 10–12 semanas totais
  • Comprometimento longo antes de ver ML rodando
D

Só o Ambiente (Gymnasium env + física)

Apenas o line_follower_env.py + physics.py — nenhum treinamento ML por enquanto. Fundação que permite tanto Corsa quanto Offroad depois.


Prós

  • Entregável claro e pequeno
  • 1–2 semanas
  • HAL validada antes de qualquer ML

Contras

  • Nada roda de ponta a ponta ainda
