# LFR v2 — Plano Mestre de Orquestração (ruflo)

> **For agentic workers:** este plano é do **coordenador** (sessão principal). Ele dispara os
> agentes que executam os planos de pacote. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Executar os três pacotes da v2 (firmware, mecânica, manuais) com agentes
especializados coordenados pelo ruflo, com avaliação independente de cada pacote, e entregar a
branch `feat/lfr-v2-retomada` integrada, verificada e com o manual HTML publicado.

**Architecture:** Swarm ruflo hierárquico. WP1 (firmware) e WP2 (mecânica) rodam em paralelo,
cada um num worktree próprio; o WP3 (manuais) roda depois do merge dos dois. Cada pacote passa
por um avaliador de outro tipo de agente, que roda os comandos por conta própria e escreve um
relatório em `docs/avaliacao/`. Achados CRIT/HIGH voltam ao executor (no máximo duas rodadas).
O ruflo guarda decisões, achados e status na memória `lfr-2026` e rastreia tarefas e agentes.

**Tech Stack:** ruflo / claude-flow MCP (`mcp__claude-flow__*`), ferramenta `Agent` do Claude
Code com `isolation: "worktree"`, git, PlatformIO, build123d.

**Spec:** `docs/superpowers/specs/2026-10-13-lfr-v2-retomada-design.md` (§7 e §8).

**Planos de pacote:**
- WP1 — `docs/superpowers/plans/2026-10-13-lfr-v2-wp1-firmware.md` (21 tarefas)
- WP2 — `docs/superpowers/plans/2026-10-13-lfr-v2-wp2-cad.md` (12 tarefas)
- WP3 — `docs/superpowers/plans/2026-10-13-lfr-v2-wp3-manuais.md` (7 tarefas)

## Global Constraints

- Branch de integração: `feat/lfr-v2-retomada`. Nenhum agente commita direto nela, exceto o
  coordenador (merges) e o WP3 (que roda depois dos merges, em worktree próprio e com merge
  pelo coordenador).
- `.gitignore` (mudanças locais do ruflo), `.claude/` e `.mcp.json` **nunca** entram em commit.
- Cada agente executor segue o seu plano tarefa por tarefa, com TDD, e termina cada tarefa com
  os testes verdes e um commit.
- O avaliador é sempre um tipo de agente diferente do executor e **não altera código**.
- Nada é publicado, empurrado (`git push`) ou aberto como PR sem pedido do usuário. A única
  publicação prevista é o manual HTML (fase P7), que é privada por padrão.
- Commits terminam com `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **Worktree criado a partir do commit errado** — o executor trabalharia sem a spec/planos.
   Cada prompt manda conferir `git log --oneline -1` contra o commit esperado antes de começar.
2. **Avaliador repetindo o relato do executor** — o prompt do avaliador exige rodar cada
   comando e colar a saída como evidência na matriz de conformidade.
3. **Conflito no merge** — `src/config.h` (`LOOKAHEAD_MM`, mexido só pelo coordenador),
   `docs/DIVERGENCIAS.md` (só o WP2 mexe antes do WP3) e `README.md` (só o WP1 mexe antes do
   WP3). O roteiro de merge da fase P4 trata cada um.
4. **MCP do ruflo cair no meio** — a execução continua com a ferramenta `Agent`; o coordenador
   registra o que faltou na memória quando o MCP voltar (`system_status` antes de cada fase).
5. **Rodada de correção sem fim** — no máximo duas rodadas por pacote; o que sobrar vai para o
   usuário com a recomendação do avaliador.
